# 页面面向 AI 的形式

目标是回答“这里是什么、当前是什么状态、能做什么、怎么做、如何确认结果”。
不要把人类界面中的菜单层级或装饰原样复制，也不要只列接口名而丢失业务含义。

按需求呈现以下内容，没有证据的留空或明确未知：

- 页面身份：站点、应用、环境、路由；账号与当前权限只从本次现场获取。
- 对象与关系：例如分组包含配置、目录条目与已安装服务不是同一个对象。
- 当前状态和数据：已选对象、筛选条件、加载/错误/空状态以及必要字段，标注观察时间。
- 动作：可达的按钮/操作、输入、输出和副作用；已验证 API、保存代码或可靠 UI 路径。
- 验证依据：如何确认操作真的完成、什么时候需要重新检查约定。

一个动作可有 API 和 UI 两种路径。选最有效且在权限内的方法，不规定所有动作必须
API 化。没有证据的按钮不猜接口；接口存在也不等于当前用户拥有执行权限。

## 兼容旧实验的页面描述（非必需）

新 WebMCP 脚本直接在工具描述和 schema 中表达能力，不要求下面的索引格式。
仅在复用已有本地站点 Skill 时，才按需使用 `scripts/page-view.mjs`；它不发现页面原生工具，
不自动执行匹配脚本。无匹配不等于没有能力，issues/unindexed 表示索引覆盖不完整。

可在独立站点 Skill 旁增加 `page.json`：

```json
{
  "version": 1,
  "title": "页面名称",
  "summary": "页面意义和需要现场确认的部分",
  "pages": [{ "origin": "https://example.com", "path": "/console", "route": "/settings" }],
  "actions": [
    {
      "id": "list",
      "label": "查看条目",
      "effect": "read",
      "file": "scripts/read.js",
      "guide": "参数、结果及使用条件，具体执行遵循 SKILL.md"
    }
  ]
}
```

origin/path 精确匹配；route 可省略，提供时匹配 `#` 后、`?` 前的 SPA 路由。
查找器不使用查询串推断账号/租户或权限；查询参数影响环境的页面要额外现场核验。
匹配结果一律 `UNVERIFIED`，不是实时账号状态。当前只支持本地显式索引，
未索引、不可读、链接目录和远端来源须保留发现边界，不能伪装为全量结果。
action.file 只能引用同一 Skill 内的文件；动作描述不授权执行，write/unknown 也不自动运行。
描述文件不是产物的运行依赖：删掉它，已有 Skill 和代码仍可独立使用。

## 必要时重构呈现

先提供与原网页并存的 AI 页面视图：结构化文本、对象表、动作表单或辅助面板皆可。
保留回到原页和核对证据的路径。是否做界面重排以减少理解/操作成本的实测为依据，
不以“看起来更简洁”为验收。不要擅自覆盖真实网站或把静态描述当作可点击的实时控件。
若将来需要替换呈现，只在明确作用域内做可恢复改动；网站业务数据仍受原权限约束。
