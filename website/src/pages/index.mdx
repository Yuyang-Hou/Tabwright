## 看见结果，也能追到原因

页面截图能说明“看起来怎样”，请求、源码和运行时能进一步解释“为什么”。
Tabwright 把这些能力放在同一个可编程环境中，由 AI 决定怎么组合。

## 从你正在使用的浏览器开始

安装 [Chrome 扩展](https://chromewebstore.google.com/detail/tabwright/dkfhphbajbkplddmchbdgdddioonngep)，
在目标页面点击扩展图标，然后安装 CLI 并检查连接：

```bash
npm install -g tabwright@latest
tabwright doctor
tabwright session new
```

CLI 附带一份简短的工具使用 Skill。把目标和页面告诉 AI，它就可以按需读取本地 API 文档：

```bash
tabwright docs network
tabwright docs editor
tabwright docs debugger
```

完整连接说明见 [安装指南](/docs/installation)，工具客户端配置见 [MCP 接入](/docs/mcp-setup)。

## 登录留在浏览器，业务知识归你

优先在目标网页中发起请求，让浏览器携带适用的登录凭据。不需要为每个 Skill
导出一份 Cookie。网站如果使用额外的签名或 CSRF 机制，仍需遵循它的实际请求方式。

需要重复使用时，让你的 AI 创建普通 Skill 和脚本。Tabwright 不注册、不扫描、
不托管这些业务 Skill；脚本按需通过 CLI 或 MCP 使用浏览器能力。

[了解独立脚本与登录态](/docs/independent-scripts)

## 强工具，清楚的边界

- 使用的是你的浏览器权限。不同会话的变量分开，但不代表账号或标签页隔离。
- 返回的页面数据会进入调用方 AI，可能由其模型提供商处理；本地日志和源码也可能包含敏感信息。
- 已知凭据字段会在诊断日志中脱敏，但任意脚本和业务响应不是自动安全的。
- 超时不代表网页操作已取消。对于结果不明的写入，先核实，不能盲目重试。
- 不提供录制、云浏览器、订阅或业务 Skill 管理；保留标准 Playwright/CDP 的组合自由。

建立在 [Playwriter](https://github.com/remorses/playwriter) 的浏览器连接基础之上。
