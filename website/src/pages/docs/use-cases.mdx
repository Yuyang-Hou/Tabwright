Tabwright gives the agent access to the page and its running application. These
examples describe useful evidence, not a fixed order of operations.

## Explain a broken page

“The dashboard loaded, but the chart is empty.”

The agent can inspect the relevant DOM and runtime state, look at console errors,
follow the chart's request and response, or pause where the application transforms
the data. A screenshot helps when the failure is visual; a response or call stack
can be more useful when the page simply displays the wrong result.

`createNetwork` provides request summaries and selected request/response details.
`createDebugger` provides breakpoints and paused-state inspection. The agent can
look up either API locally:

```bash
tabwright docs network --limit 80
tabwright docs debugger --limit 80
```

## Debug without the source repository

“Find out what this deployed page sends when I change this filter.”

Observed requests, running scripts, available public Source Maps, and Debugger
values can explain the client behavior. `createEditor` searches loaded scripts
and reads bounded excerpts. `editor.saveRaw` saves an exact script locally by
content hash; optional Wakaru analysis can help interpret packed code.

This evidence describes the client currently running in the browser. It does not
establish hidden server behavior or permissions beyond the signed-in account.

## Verify a frontend change

“Check the layout and behavior of the new settings page.”

The agent can inspect a screenshot and computed styles, query relevant DOM or
React information, use the page's controls, and inspect the resulting state.
Temporary script/CSS edits can test a hypothesis before changing the source
repository. In-memory changes normally disappear on reload.

Use a task-owned page when inspecting a new route. Use the existing user-selected
page when reproducing an issue depends on its unsaved inputs or current state.

## Investigate an authenticated workflow

“The page says saved, but the new value does not appear.”

The agent can correlate the action with its network response and resulting state
in the intended account and environment. When a request needs the site's login,
CSRF, or signatures, page interaction or the site's in-page client can supply
that context without copying credentials into agent output.

Any subsequent modification must stay within the user's authorization. An
uncertain write result is a reason to inspect current state, not blindly submit
the action again. If the site needs human verification, the user can complete it
in the shared browser.

## Read or export page data

“Extract the filtered rows from this authenticated report.”

The agent can choose rendered DOM, a structured response, or the site's export
control depending on what accurately represents the requested data. It can save
large output locally and return a useful summary or artifact path.

## Repeat a proven task

If repeated work warrants a reusable script or Agent Skill, the agent can create
one using its normal tools. Scripts can use ordinary browser execution via `-f`,
or standalone APIs without Tabwright. Reuse is optional; a one-off investigation does not require a Skill.
