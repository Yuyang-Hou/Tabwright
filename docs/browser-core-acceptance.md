# Tabwright 浏览器核心版验收

日期：2026-09-07。工作分支：`feat-agent-debugging-core`；Playwright 子模块仍在 `playwriter`。
这是暂停开发时保留的本地代码检查点，不是正式发布或部署的版本。
产品开发、官网叙事调整和发布暂停；与官方 CDP 能力的同场对照尚未进行。

## 最终产品边界

Tabwright 现在是一套可组合的浏览器理解与调试工具。AI 可以从页面、请求、
实际加载的源码和运行时变量入手，自主选择手段，不必经过录制或固定工作流。

```text
用户目标 + AI / 用户自己的 Skill
                 │ 普通代码
              CLI / MCP
                 │
       有状态执行器 + 调试工具
       页面 / Network / 源码 / Debugger / 样式
                 │ Playwright / CDP
             本地 WS relay
                 │ chrome.debugger
       扩展 → 用户选择的 Chrome 页面
```

直接连接自有 CDP、独立本地/无头浏览器和显式远程 relay 仍可用；
它们不代表继承用户常用浏览器的登录状态。

| 部分                                               | 当前状态                                                       |
| -------------------------------------------------- | -------------------------------------------------------------- |
| 页面、截图、交互、元素定位和 pin 检查              | 保留                                                           |
| Network 请求筛选、响应摘要、发起位置               | 可用，按需取得证据                                             |
| 源码搜索、保存、JS/CSS 调试和断点变量              | 可用，复用 CDP 资源状态                                        |
| 执行超时                                           | 明确说明结果可能未知；前次等待中的执行未结束时不重叠执行或重置 |
| 录制、rrweb、活动历史、回放、标注及录制工具栏      | 删除                                                           |
| 扩展 Options、业务 Skill 扫描/注册/runtime/管理    | 删除                                                           |
| 自动提取、缓存、刷新 Skill 凭据及运行历史服务      | 删除                                                           |
| 云浏览器租用、账号登录、订阅、计费和数据库服务代码 | 删除                                                           |
| 官网                                               | 产品首页 + 安装/使用文档；无登录、云服务或 AI 聊天入口         |

WS 协议版本仍为 1。旧录制消息得到“不支持”回复，旧录制数据被丢弃；
核心 CDP 不因此断开。旧 HTTP 产品接口返回 410，旧 CLI runtime 命令在执行前失败并提示迁移。

## 用户自己的 Skill

- 业务知识、脚本、校验、确认和成功判断归用户/AI 管理，不需要向 Tabwright 注册。
- 默认在正确的已登录网页中请求，浏览器携带适用凭据，不向 AI 展示 Cookie。
- 导出 Cookie 是独立授权的例外，不是失败后的自动兜底；也不能绕过 CSRF、CORS 或网站授权。
- `skill install/status` 仅管理 Tabwright 自己的简短工具说明，不扫描或管理业务 Skill。

仓库的五份业务 Skill 已迁至 [独立示例](../examples/independent-skills)：
两份使用普通浏览器 `-f` 脚本，三份保留已有 Node API 实现并显式接收限定 origin 的本地凭据。
Node 示例无 npm/Tabwright 依赖；默认只做离线输入检查，写入还要求当前输入、代码及业务契约对应的确认 hash。
离线检查不是后端预览，hash 也不是人类已批准的证明。具体业务准备与回读仍归 Skill 所有。

采用 Skill 编写指南拆开了工具说明与业务脚本；简化原则用于删除产品管理层，
没有删除业务输入校验、明确确认或结果不明时暂停的边界。
详见 [独立脚本与登录态](./independent-scripts.md) 和 [迁移说明](./browser-core-migration.md)。

真实隔离 Chrome 验收覆盖了“错误页面结果 → 请求响应 → 实际源码 → 断点局部变量”，
共享 CDP 域不会破坏已设断点，页面导航后源码更新，超时后结果核实与恢复。
登录态测试中，匿名 Node 请求返回 401，而普通浏览器脚本可使用 HttpOnly 登录 Cookie，
页面脚本看不到 Cookie 值；未使用真实业务账号或执行配置发布、CMS 修改、退款。

首轮完整回归定位并修正了退役接口的旧状态码预期和跨域 iframe 中间页面的测试竞态；
随后 Node 26 运行遇到测试进程 IPC `EPIPE`，未算作通过，改用现有 Node 22.22.0 LTS 复验。
LTS 全量运行剩一项 `showAriaRefLabels(hacker-news)` 超时；同一用例未改代码、未放宽断言，单独复测通过。
随后完整截图测试文件复测 10/10 通过（56.61 秒）。
目前不能称为全量全绿，外站标签检查的间歇性问题仍需在发布前稳定复现并定位；
本轮证据不足以把它直接归因于外站网络。没有批量更新快照或跳过失败用例。
原有两项跳过为 page.route 复现用例和需显式启用的已安装 Chrome 扩展加载检查。
