# Tabwright WebMCP 使用指南

Tabwright 自带 Skill 串联网页工具的制作与使用，无需另装 Web Code Skill。

给 AI 一个链接和你关心的能力，它先使用页面已有的 WebMCP 工具；需要沉淀新能力时，
理解网页并制作用户脚本。脚本由你选择的管理器保存，下次访问时加载。
不需要给每个网站安装一个 Skill；需要登录的操作仍使用你的浏览器状态。

## 当前架构

| 部分 | 职责 | 由谁提供 |
| --- | --- | --- |
| Tabwright 自带 Skill | 引导接入、发现/调用工具、制作和维护脚本 | 我们 |
| 脚本管理器 | 保存、加载、启停和更新脚本 | 用户选择，如脚本猫 |
| 浏览器/CDP 客户端 | 访问已登录浏览器，发现/调用工具，按需调试网页 | 默认复用 Tabwright 现有插件，也可选择其他客户端 |
| 页面 WebMCP 脚本 | 描述并执行具体网站能力 | 用户的 AI 制作或复用 |

浏览器入口在现有 Tabwright 插件链路上扩展，首版提供 WebMCP 发现与调用；
暂不开发脚本管理器或云端管理平台。不同工具组合按实际能力接入，
不宣称任意插件都有 WebMCP 支持；缺少依赖时，Skill 提供相应的最短接入指引。

## 直接这样说

首次保存：

> 用 Tabwright 把这个页面的查询能力保存下来，下次直接复用：〈链接〉。

以后使用：

> 在〈网站〉查一下〈内容〉。

检查或维护：

> 检查之前保存的〈网站能力〉还能不能用；如果是接口改版，在原范围内修好。

可明确指定 `$tabwright`。已有页面工具优先复用，不重复生成。
没有必要一次保存整个网站；从你需要的一项能力开始。

## 得到什么

默认是你持有的 `.user.js` 脚本，工具说明和输入输出约定随脚本保存。
必要时附简短证据或检查代码，不默认产出每站点 Skill、目录索引或专有运行时。
没有 Web Code 账号、云浏览器或后台服务；AI 使用你选择并授权的浏览器工具。
持久保存需要兼容的脚本管理器；使用网站已经提供的工具则不必先安装管理器。
需要权限或登录时会停下来；不会把 Cookie、令牌导出到本地 CLI。
查询结果会交给调用它的 AI 处理；留在浏览器的是登录凭据，不是所有网页数据。

可以用不同 agent 维护这些文件；实际执行仍取决于该 agent 支持的浏览器能力。
这是浏览器内执行的代码，不是可脱离 agent 独立运行的 Python CLI。

## 安装入口

入口源码在 `skills/tabwright/SKILL.md`，随 Tabwright CLI 一起分发并自动安装；
完整参考由 `tabwright docs browser` 提供，不依赖单独的 Web Code 文件夹。
如果安装时禁用了生命周期脚本，可运行 `tabwright skill install`，并用
`tabwright skill status` 核对版本。保留用户修改，不自动强制覆盖。

WebMCP 完整工作流随 Tabwright 4.0 的 CLI 和自带 Skill 分发。升级后用
`tabwright skill status` 确认版本；仓库源码变化本身不会更新已安装副本。
`skills/web-code/` 暂时保留为可选兼容入口，Tabwright 用户无需安装它。
网页脚本仍由所选脚本管理器保存；卸载 Skill 不会删除管理器中的脚本。
分享时只交付审核过的文件，不附带内部账号或业务数据。

## 支持范围与验收

首版发现指定顶层页面的原生 WebMCP 工具，不聚合 iframe。需要浏览器支持
`document.modelContext.getTools/executeTool`；不支持时返回明确错误，不注入 polyfill。
脚本管理器负责持久加载；Tabwright 负责发现与调用，刷新、导航或工具变化后需重新发现。

已通过隔离 Chrome 的原生工具、扩展/relay、MCP/CLI、输入校验、会话生命周期和超时检查。
业务工具使用本地合成样例，没有将模拟结果当作真实业务写入验收。
查看 [WebMCP 验收记录](../openspec/changes/tabwright-webmcp/validation.md)。

没有“任何网站自动修复”的保证；具体脚本仍需验证。发现工具、维护代码或调用成功
都不等于获得业务写入授权。结果未知时不要自动重试。
